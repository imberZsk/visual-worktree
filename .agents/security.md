# 安全约束

## 凭据与配置

- 不读取、打印、提交或回显 token、密码、cookie、私钥及包含凭据的环境变量。
- 项目级 `.npmrc` 只允许公开、无凭据的 registry 和 Electron 镜像配置；私有 registry、认证 token 与内网地址放在用户级 `~/.npmrc`。
- 日志与错误信息不得包含完整环境变量、授权头、用户主目录中的敏感文件内容或远程 URL 凭据。
- AI、Jira、SSO、飞书等环境变量只在执行边界按需读取，不写入仓库配置或持久化历史。

## Electron

- 保持 `contextIsolation: true`、`nodeIntegration: false` 和生产 CSP；不得为解决局部问题整体放宽安全策略。
- preload 只暴露白名单业务能力，不暴露任意命令执行、任意文件读写或原始 `ipcRenderer`。
- IPC 参数视为不可信输入：校验类型、长度、协议、路径归属和允许操作。
- 打开外部 URL 前限制为明确允许的协议；禁止把未校验字符串直接交给系统 shell。

## 文件与命令

- 删除、移动、覆盖文件前解析准确目标；递归操作不得指向主目录、仓库根目录或未解析变量。
- 路径必须验证在配置根目录内，比较时使用规范化后的绝对路径，防止 `..`、符号链接或大小写差异越界。
- 外部命令优先使用参数数组和 `execFile`/`spawn`；确需 shell 模板时对每个动态值使用与目标 shell 匹配的引用函数。
- 未经用户明确授权，不执行不可逆 Git 操作、强推、发布、删除远端资源或修改系统级配置。

## 依赖与发布

- 新依赖使用官方包名并检查锁文件变化，不执行来源不明的安装脚本。
- 构建产物不打包开发机配置、日志、会话记录、测试夹具或凭据文件。
- 安装包未签名是已知发布属性，必须如实提示，不能通过关闭系统安全检查伪装为已签名。
