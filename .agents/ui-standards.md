# UI 与交互规范

## 设计基础

- 修改或新增任何 UI 前，必须先阅读本文件和 `style-standards.md`；二者是实现与验收约束，不是可选建议。
- Ant Design 是项目唯一的基础设计系统：优先使用 antd 组件、主题 token 和 `@ant-design/icons`，不引入 Tailwind 或第二套颜色/间距工具链。
- 项目规范只在 antd 之上定义业务语义和组合节奏；新样式先找对应 token，不复制一套固定主题色。
- UI 应保持安静、紧凑、适合反复扫描；信息层级主要依靠间距、字重和语义色，不依靠装饰性渐变、大阴影或多层卡片。

## 间距系统

所有新增布局使用 4px 基准的有限梯度，不在 JSX 中临时填写无语义的 `margin` / `gap` / `padding`。

| 数值 | 语义            | 典型场景                                      |
| ---- | --------------- | --------------------------------------------- |
| 4px  | 紧密关联        | 图标与短文字、列表项内标题与状态              |
| 8px  | 控件内/同组关系 | 控件与其辅助说明、同一列表的重复项、行内操作  |
| 12px | 关联内容        | 辅助说明与列表/操作区、紧凑列表项的水平内边距 |
| 16px | 子区块          | 小标题与子内容、表单内部两组关联字段          |
| 24px | 同级模块        | 两个表单字段、设置页两个配置模块              |
| 32px | 主要区域        | 页面主分区或不同业务阶段                      |

设置类表单固定使用以下垂直节奏：

1. 标签到控件使用 antd 垂直 `Form.Item` 默认节奏（当前为 8px）。
2. 控件到所属辅助说明为 8px，辅助说明必须在对应字段内。
3. 列表顶部说明到列表、列表到新增操作均为 12px。
4. 同一列表内的重复项为 8px，同级表单字段/配置模块为 24px。
5. 不用 `<br />`、空白文字或叠加多层 `Space` 制造垂直间距。
6. 不能临时创造 6px、10px、14px、18px 等布局间距；现有梯度不能表达需求时，先说明设计语义并更新本规范，再实现新取值。字号、行高、控件高度和响应式断点不属于布局间距，但仍须集中定义。
7. 空列表不得保留无内容的列表、滚动或占位容器；Flex/Grid 的 `gap` 只应作用于实际可见的相邻内容，空态新增按钮直接承接标签到控件的 8px 节奏。

## 颜色系统

### Visual Worktree 标准色板

所有桌面项目使用 Ant Design 默认 seed `colorPrimary: #1677ff`，再分别通过 `defaultAlgorithm` / `darkAlgorithm` 派生主题；禁止按主题手写另一套 `colorPrimary`。当前锁定的关键结果如下：

| 语义                 | 亮色      | 暗色      | 使用场景                       |
| -------------------- | --------- | --------- | ------------------------------ |
| `colorPrimary`       | `#1677ff` | `#1668dc` | 主按钮、当前导航、焦点、链接   |
| `colorPrimaryHover`  | `#4096ff` | `#3c89e8` | 仅用于 hover，不能作为暗色主色 |
| `colorPrimaryActive` | `#0958d9` | `#1554ad` | 按下态                         |
| `colorPrimaryBg`     | `#e6f4ff` | `#15325b` | 低强度选中背景                 |
| `colorSuccess`       | `#52c41a` | `#49aa19` | 成功、完成                     |
| `colorWarning`       | `#faad14` | `#d89614` | 警告、需注意                   |
| `colorError`         | `#ff4d4f` | `#dc4446` | 错误、阻断、危险操作           |
| `colorBgLayout`      | `#f5f5f5` | `#000000` | 页面底层                       |
| `colorBgContainer`   | `#ffffff` | `#141414` | 侧栏和主要容器                 |
| `colorBgElevated`    | `#ffffff` | `#1f1f1f` | 卡片、弹层、浮层               |
| `colorBorder`        | `#d9d9d9` | `#424242` | 控件和主要边界                 |

- 业务组件必须消费 Ant Design token 或与上表一一映射的语义 CSS 变量，不直接写主色、状态色和主题中性色。
- 启动页无法读取 React token 时，允许静态使用上表的 `colorPrimary`；亮色为 `#1677ff`，暗色为 `#1668dc`。
- `#4096ff` 只能表示亮色 hover；不得再作为暗色默认主色、常驻图标色或 loading 色。
- 图表、代码高亮和第三方平台品牌色属于独立数据语义，必须使用专用变量，并且不能覆盖应用交互主色。

- 主操作、当前导航和可交互焦点使用 `colorPrimary` 系列；主色不用于普通装饰或无状态的大面积背景。
- 正文、次级说明、弱化元信息和禁用文字分别使用 `colorText` / `colorTextSecondary` / `colorTextTertiary` / `colorTextDisabled`。
- 容器、弱化区块和重复列表项使用 `colorBgContainer` / `colorFillAlter` / `colorFillQuaternary`，边界使用 `colorBorderSecondary` 或 `colorBorder`。
- 成功、警告、失败和信息状态只使用 `colorSuccess` / `colorWarning` / `colorError` / `colorInfo` 系列；红色只表示错误、阻断或危险操作。
- 不在业务组件中写 `#999` 一类固定中性色，不为明/暗主题各自复制一套可由 token 表达的颜色。

## 组件选择

- 开发 UI 时必须先确认 antd 是否已有合适组件，优先使用 antd 与现有项目封装。
- 熟悉操作使用图标按钮；明确命令使用图标加文本或文本按钮。颜色选择、模式切换、布尔值和数值分别使用合适的标准控件。
- 页面专用逻辑放在页面组件或对应 hook；只有多个页面确实复用时才创建共享组件。
- 复杂组件中的业务流程优先拆入相邻 hook，纯计算拆入 `*Logic.ts`，组件保留数据绑定与渲染。
- 配置页的重复项使用「摘要行 + 详情弹层」或紧凑行；同一容器中不并排多套完全展开的长表单。
- 同类列表的新增操作使用全宽虚线按钮；排序、编辑和删除放在稳定的行尾操作区，纯图标按钮必须有可访问名称或 Tooltip。
- 带可见文字且语义已明确的按钮不要重复添加同文案 Tooltip；窄屏隐藏文字时仍保留稳定的 `aria-label`，只有无法从图标或可访问名称理解的补充信息才使用 Tooltip。
- macOS 自定义标题栏必须在交通灯右侧保留至少 `27px` 视觉缓冲；当前 Header 左侧安全区固定为 `96px`，标题和交互控件不得侵入系统窗口按钮区域。

## 状态完整性

- 每个异步动作必须覆盖初始、loading、成功、空数据和失败状态。
- loading 应绑定到实际任务或项目标识，避免一个项目操作锁死全页面；同一动作执行期间阻止重复提交。
- 主视图首次请求数据时，必须在切换视图前同步进入 loading，并在对应内容区域使用与同级视图一致的小号 `Spin`；短时切换只显示 loading，不显示“正在加载…”等可见文案，但需保留无障碍名称。不得先闪空态，也不得使用阻断顶部导航的全屏遮罩；只有需要解释阶段或进度的长任务才配文字说明。
- Electron 冷启动在 React 首次提交前使用 `index.html` 内的主题背景、居中项目图标和图标下方的 Ant Design 默认四点 `Spin` 形态；图标固定为 `112px` 并保持窗口几何中心，loading 容器为 `20px`、单点为 `9px`、与图标间距为 `16px`，同时适配明暗主题和减少动态效果设置。启动资源必须轻量、无额外文案或装饰，React 挂载后由根节点自然替换，不新增独立 Splash 窗口或人为延长启动时间。
- 失败提示说明失败对象和可操作原因，不能只显示“操作失败”；详细 stdout/stderr 使用现有输出弹层承载。
- 批量操作展示总量、当前项和逐项结果，单项失败不抹掉已成功结果。
- 弹层关闭、组件卸载或任务切换时清理监听器、计时器和过期异步结果，避免旧结果覆盖新页面。

## 交互效率

- 高频操作保持在当前工作区可达，不增加无必要的确认步骤；删除、覆盖等危险操作使用现有确认弹层默认配置。
- 保留键盘焦点、可访问名称和合理 tab 顺序；只有鼠标悬停才能发现的功能必须有 Tooltip 或其他可达入口。
- 用户输入在提交前规范化并校验，错误靠近对应控件展示；关闭弹层是否保留草稿遵循同类弹层现状。
- 路径、仓库名、任务名和分支名显示真实值，不为了美观改变业务数据。

## 响应式与主题

- 以 Electron 常用桌面窗口为主，同时验证较窄窗口；文字、徽标和操作区不得重叠。
- 任务标题徽标过多时沿用现有横向滚动/紧凑展示策略，不能把右侧操作推出可视区域。
- 同时验证明暗主题以及 hover、focus、disabled、loading、error 状态。
- Electron 自定义标题栏只保留应用内容 Header：Header 空白区域使用 `-webkit-app-region: drag`，所有按钮、输入、选择和导航控件必须使用 `no-drag`；macOS 避让交通灯，Windows/Linux 保留系统窗口控件并同步应用主题。
- 避免视口宽度驱动字号缩放；通过容器约束、换行、省略和 Tooltip 适配长内容。

## UI 变更检查清单

每次新增或修改 UI，AI 必须在完成前逐项确认：

1. 同类模块是否复用了相同的组件结构、间距变量和操作位置。
2. JSX/TSX 中是否出现固定的 `margin`、`padding`、`gap`、颜色、边框、圆角、阴影或布局尺寸；出现则迁移到相邻组件 CSS。
3. 颜色是否来自 Ant Design 语义 token，危险色是否只用于错误、阻断或删除动作。
4. 新增间距是否属于既定 4px 梯度，并且与元素之间的关系一致。
5. 图标按钮是否有 `aria-label` 或 Tooltip，表单错误是否靠近对应控件。
6. 明暗主题和窄窗口是否都无重叠、裁切或不可达操作。
7. 是否补充与风险匹配的组件测试；固定设计规则能静态验证时，必须增加防回退测试。
