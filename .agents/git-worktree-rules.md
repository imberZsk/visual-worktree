# Git 与 Worktree 规则

## 开发工作区

- 小功能默认直接在当前分支开发，不额外创建 worktree；只有需求确有隔离价值或用户明确要求时才创建。
- 用户明确要求使用 worktree 时，从创建分支开始就在目标 worktree 内完成全部代码、测试、`CHANGELOG.md` 和版本修改。
- 不得先在主工作区修改后迁移，不得把主工作区已有未提交改动带入 worktree 或作为中转。
- 合并后更新主分支时必须原样保留用户已有改动；worktree 使用结束后按用户授权完成合并和清理。
- 未经明确授权，不执行 `git reset --hard`、强制 checkout、强推、删除分支或递归删除目录。

## 产品中的 Worktree 行为

- 目录模型保持 `worktreesRoot/{任务名}/{项目名}`，不得擅自扁平化或改变任务/项目名。
- `addWorktree` 必须保持幂等：目标已是合法 worktree 时复用并补齐缺失的 `node_modules` 链接，返回 `reused: true`。
- 创建 worktree 继续通过 `core.hooksPath` 指向平台空设备跳过 hooks，并保留 simple-git 的安全选项。
- 删除 worktree 前先用 `lstat` 确认并移除 `node_modules` 链接；绝不能递归删除链接指向的源目录。
- 删除、清理和 prune 前重新读取当前 Git 状态，不能依赖 UI 中可能过期的扫描结果。
- 主分支操作保留配置化的 `master/main` 候选与现有兜底顺序，不硬编码单一分支名。
- 批量 Git 操作逐项执行并上报进度，单项目失败以结构化结果返回，不阻断其他项目。

## 路径与命令安全

- 用户可见的仓库目录名保持原值，不自动分词、改大小写或美化。
- 复制到终端的 POSIX 路径继续使用单引号包裹并转义内部单引号。
- 所有 Git 命令限定在已解析并验证的仓库路径内；删除空父目录时不得越过配置的 worktree 根目录。
