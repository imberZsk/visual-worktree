# 样式规范

## 一致性

- 延续现有 Ant Design 主题、间距、字号、圆角和状态色；修改前先检查相邻组件与 `src/ui/styles.css`。
- 优先使用 antd 组件属性、主题 token 和现有 class，不用大量内联样式复制同类视觉规则。
- 页面区块保持安静、紧凑、便于扫描；不要引入营销式大标题、装饰性渐变、悬浮大卡片或无业务意义动画。
- 卡片只用于重复条目、弹层或确实需要边界的工具，不在卡片里再嵌套装饰卡片。

## 布局

- 固定格式控件使用稳定尺寸、grid/flex 约束和 `min-width: 0`，动态内容不得导致工具栏、表格列或折叠头跳动。
- 长任务名、路径、分支名和错误文本必须支持省略、换行、Tooltip 或滚动，不得遮挡相邻操作。
- 内容区滚动由既有内部容器承接，保持文档级 `html/body/#root` 不滚动。
- 滚动条出现时保留既有稳定宽度策略，避免数据加载前后横向布局偏移。
- 小窗口与窄宽度下仍需保留主操作；次要信息可省略或滚动，但不能与按钮重叠。

## 视觉细节

- 紧凑工具控件圆角不超过现有 antd 观感，避免过度胶囊化。
- 图标优先使用 `@ant-design/icons`；仅库中没有品牌图标时复用 `src/ui/icons.tsx` 的本地实现。
- 图标按钮提供可访问名称或 Tooltip；纯装饰图标使用正确的 `aria-hidden`。
- 动画短促且不改变布局尺寸；尊重现有弹层居中与视图淡入行为，不新增影响频繁操作的过场。
- 同时检查明暗主题，禁止只在当前主题下调整颜色、阴影或边框。

## CSS 修改

- 选择器范围尽量绑定业务 class，避免无边界覆盖全部 antd 内部结构。
- `src/ui/styles.css` 只保留页面根布局、跨页共用样式和第三方全局修正；页面/组件专用样式放在组件同目录的 `ComponentName.css` 中。
- 组件样式文件必须用唯一根 class 限定作用域，如 `.settings-surface`；不将页面专用 class 提升为无边界全局规则。
- 固定间距、排列、尺寸和响应式规则写入 CSS；只有运行时计算值、数据驱动几何值或无法由 CSS token 表达的动态主题值才使用 JSX 内联样式。
- 组件内多处重复的间距/尺寸必须使用有语义的 CSS 变量，不散落裸数字；间距取值遵循 `ui-standards.md` 的 4px 梯度。
- 使用 `gap` 组织列表时必须检查空态 DOM；不可见的空列表/滚动容器也会占据一个布局子项，必须条件渲染或移除，不能靠覆盖 margin 抵消重复间距。
- 必须覆盖 antd 内部样式时，记录对应组件版本/DOM 原因，并添加针对性回归测试。
- 不用 `!important` 作为默认方案；只有第三方优先级无法通过合理作用域解决时才使用并说明原因。

## JSX 行内样式边界

- 业务组件默认禁止使用 `style={{ ... }}`、`styles={{ ... }}` 或通过 `*Props` 传入固定 `style`。固定的 `display`、`width`、`height`、`margin`、`padding`、`gap`、字号、行高、颜色、背景、边框、圆角、阴影和滚动规则必须放入相邻组件 CSS，并通过业务 class、`rootClassName` 或 antd `classNames` 绑定。
- `width: '100%'`、`marginBottom: 0`、`color: token.colorTextSecondary` 等看似简单的值也属于固定视觉规则，不能因为代码少就留在 JSX。
- 优先使用 antd 公开语义属性表达组件状态和规格，例如 `block`、`danger`、`type`、`size`、`status`、`Typography type` 和语义化 `Tag color`；这些组件 API 不视为行内样式。
- 唯一允许的行内样式是运行时才能确定、且无法由 class/CSS 变量表达的数据驱动几何值，例如依据实际测量结果计算的坐标或宽度。使用时必须在代码旁注释数据来源和不能使用 CSS 的原因，不得夹带任何固定间距或颜色。
- 需要把运行时值交给 CSS 时，优先只设置有业务语义的 CSS 自定义属性，由样式表负责布局和视觉规则；不得把整个固定样式对象留在组件内。
- Ant Design 主题 token 若只决定固定视觉外观，应在组件 CSS 中使用对应 `--ant-*` 语义变量；只有 JS 配置或数据驱动状态确实需要数值时才在组件内调用 `theme.useToken()`。

## 样式归属与验收

1. 修改前先判断规则属于全局、跨组件复用还是单组件，分别放入 `src/ui/styles.css`、已有共享样式或相邻 `ComponentName.css`。
2. 单组件 CSS 必须由唯一根 class 限定作用域，弹层使用 `rootClassName`，避免选择器泄漏到其他 antd 组件。
3. 写完后搜索本次改动组件中的 `style=`、`styles=`、固定色值和非规范间距；除上述运行时例外外必须清零。
4. 执行格式检查、相关组件测试、明暗主题与窄窗口视觉验证；共享样式或主流程改动还要执行完整测试和构建。
5. 对已经完成样式收敛的关键组件增加静态测试，阻止固定行内样式、裸色值或组件专用规则重新进入全局 CSS。
